# Implemented feature commands

This is the live command inventory, not the list of planned commands. Requirements are in [pseudo-OS architecture](pseudo-os-architecture.md); progress is tracked in the [backlog](pseudo-os-backlog.md).

## Browser-local interface

The mounted desktop exposes `globalThis.jesteros` with:

- `execute(request)`: asynchronous command invocation. Resolves to an applied/rejected result. Applied results wait for the Svelte DOM flush and capture live scroll positions after focus/anchoring/layout effects; they do not claim completion of future media/progress animations. Await each result when sequencing dependent commands.
- `inspect()`: a detached snapshot of supported command names and current window/application state. Changing this snapshot does not change the scene.
- `describe()`: detached, JSON-serializable version-1 catalog for the active profile. Includes supported profile IDs, capability, request/success-result JSON Schemas, runtime requirements, data/presentation effects, completion semantics and current target identities. Read `describe().commands[name]` for a Golden Gate command; querying never activates a window or changes the scene.

The default Golden Gate27.0.1 exposes323 commands; preserved Mojave178/Sonoma163/High Sierra170/Windows190 remain selectable. New feature work is latest macOS only. The stable public object follows native remounts; during transition dispatch/discovery reject unavailable and inspect reports profile:null/transitioning:true. Immutable profile identity/coverage and native adapters are not a theme selector. Rust transport/controller remain deferred.

Requests contain `command`, optional `requestId`, `target`, and `payload`. Command targets/payloads are plain JSON objects; omitted target/payload become empty objects. Explicit null, arrays, unrecognized request fields, unknown commands, and invalid command arguments are rejected. A supplied requestId must be a nonempty string and is echoed in results.

Results are `{ status: 'applied', target: ... }` or `{ status: 'rejected', error: { code, message } }`, plus requestId when supplied. Validation/unavailable-target failures do not apply a scene mutation. Programming errors are not silently translated into successful cues.

## Machine-readable catalog

`frontend/src/command-catalog.js` composes the canonical shared/native/session/power/seed/saved-session/menu-bar inventory. Registration requires exact descriptor/handler parity for the selected layer and seals handlers. Golden Gate's `SessionHost` owns session/power/setup/shared-menu operations, including existing provider-scoped menu names, and delegates canonical private App actions. Legacy scenes retain their private menus and reject the eight Golden-only navigation/owned-command names as unsupported_profile before writes. Unregistered features are never advertised. Keep behavior tables and working notes current.

`jesteros.describe()` returns `{ version:1, profile, profiles, commands, targets }`. Active profile metadata and snapshots identify the actual native scene. Profiles list supported IDs; targets.profiles lists installed profile IDs/names/family/version. Each commands entry has:

- `requestSchema`: [JSON Schema Draft 2020-12](https://json-schema.org/draft/2020-12/schema) for the complete command envelope, including closed target/payload objects and conditional argument rules. [Conditional schemas](https://json-schema.org/understanding-json-schema/reference/conditionals) capture paired context coordinates, mutually exclusive menu positioning, explicit pin payloads, and observational focus constraints.
- `resultSchema`: successful applied-response schema. Returned identities are inside **result.target**, never flattened beside status. app.open returns target.appId/windowId; desktop.open also returns target.fileId; notes.create returns target.noteId; scene.selectProfile returns target.profileId. Registered Launchpad presentation returns windowId:null from app.open, desktop.open and dock.activate. Rejected responses use the shared error envelope above.
- `profiles`, `capability`, `requires`: current profile support and descriptive runtime prerequisites. Dispatch and composed handlers require both the active profile ID and capability; unsupported_profile rejects before mutation. Discovery omits unsupported commands. Schemas validate JSON shape, not current record/menu availability; handlers remain authoritative for scene-dependent rejection.
- `effects.data`, `effects.presentation`, `completion`: record mutation versus selection/focus/menu/window effects, with promise completion after handler state, Svelte DOM flush, and retained native scroll bookkeeping. No current command promises completion of future media/animation.

Targets contain installed profiles, registered apps/coverage, live desktop-file and window identities, and native state-specific targets. macOS exposes minimized/zoomed windows, Window menus and Notes folder/search/deleted identities. Windows exposes minimized/maximized windows plus `targets.native.shell` panels/files/controls/calendar/notifications. `targets.native.apps.applications[appId]` contains `windows`, each with its exact windowId, data, menus/dialogs and mounted presentation targets, plus `retained` for closed-only data. `targets.applications` remains the common app array; native discovery does not overwrite it. Hidden/inert views are unavailable presentation targets. Queries are detached and follow live changes without activating them.

Managed application targets include logical `minimumSize:{width,height}`; shell presentations do not. Live window targets include detached physical workspace `bounds:{x,y,width,height,scale}` and `resize:{available,edges,minimumSize}`. `edges` lists `n,s,e,w,ne,nw,se,sw`; availability excludes minimized, expanded and global-modal-blocked windows. Querying or mutating these returned objects never changes geometry.

Common application targets report `multipleWindows`, `quitAllowed`, `running`, `active`, `quitting` and `windowIds`. Inspection exposes `activeAppId`, `runningAppIds` and `pendingQuitAppIds` separately from window focus/lifetime. Native application commands accept an optional `target.windowId`, validate ownership, and require it when multiple windows make the target ambiguous. A stale or wrong-owner ID rejects without mutation. Window-local generic text selection is `textSelection`; Snipping's domain `selection` remains its crop rectangle.
Launchpad discovery additionally reports `presentation:'launchpad'`, `coverage:'shell-launcher'`, multipleWindows:false and quitAllowed:false. Opening it retains the original active app/window and never adds running/MRU/recent entries or a managed-window target.

```js
const catalog = jesteros.describe('app.open');
const appId = catalog.targets.applications.find((app) => app.name === 'Notes').appId;
const result = await jesteros.execute({ command: 'app.open', target: { appId } });
if (result.status !== 'applied') throw new Error(result.error.message);
const windowId = result.target.windowId;
```

## Inventory

The tables below identify profile support for each implemented slice. Unexpected target/payload fields and invalid types are rejected. Application IDs and window IDs are distinct; use returned/live window IDs, including for newly created windows. Closed IDs are never reused within a scene.

### Native scene selection

| Command | Target | Payload | Behavior |
| --- | --- | --- | --- |
| `scene.selectProfile` | `{ profileId }` | `{}` | Selects an installed native profile. Same ID preserves state. A different ID disposes the old scene and mounts fresh native data/windows/menu/focus/scroll state; completion waits for the new DOM and command registration. ### Scene reset and complete seed replacement

Golden Gate only, capability `scene.seed`; browser-local setup with no actor-desktop control, host service or profile migration. Seed replacement does not persist data; reset additionally clears the separate browser-local saved-session slot.

| Command | Target | Payload | Behavior |
| --- | --- | --- | --- |
| `scene.reset` | `{}` | `{}` | Clears only the Golden Gate saved-session storage slot before disposal, then restores the original default V1 fixture. Storage failure rejects unavailable without changing the live scene. |
| `scene.replaceSeed` | `{}` | `{ seed }` | Validates a complete V1 replacement before any disposal; no partial merge or automatic save. Leaves the existing saved-session slot unchanged. |

Both return `{ profileId:'macos-golden-gate-27.0.1', version:1, source:'default'\|'replacement' }`, with requestId when supplied. Available through lock/login/Guest confirmation and all power phases; completion waits for fresh active-root registration/DOM and ready default Messages. Old editors, private drafts, menus, user roots and timers are discarded. Queued outgoing commands reject unavailable; the three-method public object retains its identity. Invalid seeds reject invalid_arguments atomically; historical profiles reject unsupported_profile and do not advertise either name.

`inspect().state.sceneSeed` and `describe().targets.sceneSeed` expose `{ source, seed }`; discovery additionally declares complete replacement and false operatorDesktopControls/persistence/hostServices/profileIdentityChange boundaries. This detached **initial baseline is not current edited data**. Each fictional user independently clones it. Selecting the current profile preserves it; reload or leaving/returning resets it.

Complete Golden V1 top-level shape is `{ version:1, notes, files, printing, editing, viewing, communications, system, messages, appearance, dock }`. Exact field/item schemas are in `describe().commands['scene.replaceSeed'].requestSchema`; older incomplete V1 seeds/snapshots reject atomically, with no default-merge compatibility alias:

- `notes`: `timeBase`, `notes[{id,text,pinned,deleted,createdAt,updatedAt}]`, `selectedId`, `folder`, `search`, `sidebarVisible`, and required closed `preferences:{sortBy:'date-edited'|'date-created'|'title',groupByDate:boolean,textSize:integer12..24}`. Unique note IDs, ordered representable timestamps and a selected item in the visible folder/filter, or null. Empty notes are valid. Older incomplete Golden V1 seeds/snapshots without preferences reject; no silent default merge.
- `files`: `files`, `nextFileId`, `sceneTime`. Each user record requires `id,parentId,name,kind,appId,icon,content,deleted,revision`; kinds are folder/document/image. Optional timestamps/tags and payload-only `inCloud`, `localResident`, `deletedAt` follow the closed schema. Canonical live disk/desktop/documents/downloads/icloud-drive/mail-cache/trash folder anchors are required. Nonresident content requires retained cloud backing or iCloud/Mail ancestry; deletion time belongs to a directly trashed record and cannot exceed the scene clock. Parents must exist and be folders; cycles, protected application namespaces, invalid names and case-insensitive live sibling collisions reject. Allocation counters must exceed existing file-N IDs. Generated read-only application records remain separate.
- `communications`: required closed `{timeBase,nextId,contacts,drafts,outbox,selected:{contacts,mail,messages}}`; exact entity fields, channel membership, immutable attachments, allocation/clock/selection invariants and capacities are described under MENU-09 below. Not live accounts/inboxes or sample conversation edits.
- `system`: required closed `{computerName,recentItems:{applications:[appId],documents:[fileId],servers:[serverId]},servers:[{id,name,folderId,available}],storage:{storeInCloud:boolean,optimizeStorage:boolean,emptyTrashAutomatically:boolean}}`. Computer/server names are literal, non-whitespace, single-line and at most256 UTF-16 units. Histories have unique safe IDs, at most ten per category, newest-first; apps must be registered and server IDs must name definitions. At most128 unique server definitions map to virtual folder IDs; existing backing records must be folders, while missing/trashed/offline locations remain unavailable. Documents include image records and can outlive deletion. Clear preserves definitions, Dock usage and file-open metadata; old timestamps cannot revive history. Storage policies operate on real backing/resident payload and scene-clock Trash. Older incomplete V1 rejects without default-merge shims.
- `messages`: `pinned[{name,initials,tint,selected}]`, `conversations[{name,initials,tint,time,preview}]`, `thread{name,initials,tint,timestampLabel,timestamp,items}`. At most one selected pin; hex tints and valid UTC ISO timestamps. Thread items are incoming/outgoing literal `text` with optional sender/delivery, or the built-in original `trail` illustration with optional sender. No arbitrary media/URLs/HTML execution; empty collections remain empty. Original conversation controls remain noninteractive; actual text may be selected for independent Services workflows.
- `appearance`: supported light/dark mode, eight preset accents and preset/custom hex highlight.
- `dock`: persistent pins/order/recent usage, preferences, folder aliases and folder preferences only. Finder is first/pinned; order/history/sequence must agree and aliases must target live eligible folders. Transient focus/hover/drag/context/window tiles are not seed data.

Bounds: 1,024 notes/user files/conversations/thread items;128 pinned conversations;64 tags per file;1Mi UTF-16 units per content string;4Mi aggregate string/key units; safe ASCII IDs up to128 characters excluding prototype keys. Only plain serializable closed data: no getters, symbols, sparse arrays, exotic prototypes or cycles. Counters leave room for one safe increment; numeric timestamps leave room for one increment within the Date range. Dock size16–128 and magnification32–192. See the actual schema for each required field, allowed association/icon and remaining per-field bound.

### App retention and explicit browser-local saved sessions

Golden Gate only, capability `scene.saved-session`; setup through the existing browser API, not an actor/operator panel. Root-owned app data survives ordinary close/quit. The last ordinary closed window retains its title, normal/zoom restore geometry, Finder location/selection, Settings pane and owned native view state. Reopen gets a fresh monotonic ID on the current ordinary desktop, nonminimized and outside a retired full-screen presentation. Utility closure does not overwrite ordinary memory. `window.create` ignores remembered windows. Other profiles retain their historical policy; launch-only interiors remain launch-only.

| Command | Target | Payload | Behavior |
| --- | --- | --- | --- |
| `scene.session.save` | `{}` | `{}` | Captures every retained local root, validates the complete snapshot and synchronously replaces the one origin-local slot. No automatic save. Pending Split View choice/quit rejects unavailable before capture. |
| `scene.session.restore` | `{}` | `{}` | Reads/validates the entire stored snapshot before disposal, then restores its baseline, local models, windows and owned view state. Completes after every saved root is ready, awake at signed-out login. Never restores authentication. |
| `scene.session.clear` | `{}` | `{}` | Removes only the saved-session slot. Current model, DOM, selection, private credential drafts and presentation remain unchanged. |

Applied target is `{ profileId:'macos-golden-gate-27.0.1', version:1, saved:true }` for save/restore or `saved:false` for clear, plus requestId when supplied. All session/power phases permit setup. Missing restore rejects not_found; malformed JSON, wrong version/profile, invalid scene invariants or oversized snapshots reject invalid_arguments; quota/denied/read/remove errors reject unavailable. Validation/storage failures preserve original roots and state. Programming capture/readiness/remount errors propagate rather than becoming a fake successful fallback.

Storage key: `jesteros:macos-golden-gate-27.0.1:saved-session:v1`. Reload and profile return still start defaults; existing storage remains but is never automatically applied. `scene.reset` clears this slot before replacing the scene; `scene.replaceSeed` and leaving the profile do not clear it. Other origin keys are untouched. This is browser-origin-local persistence, never Rust/controller/server state, host authentication or secure credential storage.

Closed envelope: `{ version:1, profileId, baseline:{source,seed}, locals:[{userId,scene}] }`. `savedSessionSchema` in `frontend/src/saved-session.js` specifies the exact storage format; command request schemas accept no snapshot payload. Baseline is the initial complete seed. Each saved local scene contains its current complete seed, exact generated-catalog timestamps, runtime Dock order, live windows, last ordinary closed-window/view records, allocation/activation/creation histories, running/hidden apps, ordinary/derived Spaces and Split View ratios, persistent desktop selection/placements/options/Stacks and semantic view/Notes scroll tokens. Runtime Dock order includes eligible running aliases/minimized tiles; current seed order contains only persistent pins/folder aliases.

Only retained `local-alex` and optional `local-casey` are stored. Guest, password drafts, signed-in/locked state, power/progress, popup/drag/hover state and canonical focus pointers are excluded. Static semantic Notes title/body/search selection and owned scroll keys are permitted; matching-note offsets clamp to current text/scroll extent, readonly readers remain readonly and inert controls do not receive focus. Generated app identity/name/location is regenerated unchanged; created/modified/added/last-opened timestamps are restored independently.
App-owned About/Notes Settings utilities persist their unique app/kind ownership and static `application-about`/`application-settings` scroll keys. They never carry note-editor selections/focus or ordinary Finder/Settings fields. Their creation does not consume remembered ordinary records; utility closure cannot replace them. Notes preferences round-trip independently for each local root. Opaque utility return-focus nodes remain private to the retained root and are not saved.

Limits: at most2Mi UTF-16 serialized units, two local roots,1,024 windows/views/history/placements,66 closed-app records and16 ordinary desktops, plus complete-seed field bounds. Only closed plain serializable data; no getters, symbols, sparse/exotic arrays/prototypes or cycles. Validate registered ownership, IDs/counters, exact live view/catalog/Dock sets, active/running relationships, file associations, HOME/full-screen/Space/Split View consistency and static semantic ownership before store/remount. Browser quota may reject below the format limit; no partial or silent fallback.

Resize coordinates use the same physical workspace origin as `window.move`, not global screen or logical app-surface coordinates. A corner supplies both axes; a side supplies exactly one. Normal logical dimensions survive minimize, zoom/maximize restoration and viewport refitting. Native scale can decrease in a smaller workspace and recover on enlargement; positions may clamp. Minimum sizes are conservative implemented-layout limits, not researched factory minimums. Repeated same-area layout refresh preserves exact resized bounds.

All installed profiles support `shell.window-create` and `app.lifecycle`. macOS browser-delivered Command/Ctrl+N creates an allowed active-app window outside editable controls; Command/Ctrl+Q quits the active app. Notes keeps its own new-note shortcut. Windows native New Window/Exit controls use the same contracts; Explorer/Edge use Ctrl+N and Notepad uses Ctrl+Shift+N, leaving Ctrl+N as new tab. These do not override shortcuts intercepted by the host.

In Golden Gate, `app.open` with no live window also restores the last ordinary view described above; close/quit do not erase models or this memory. An explicit title overrides the remembered title. Reopen preserves zoom/normal restore geometry but allocates a new ID on the current ordinary desktop; `window.create` remains fresh and utility closure cannot replace the ordinary record.
