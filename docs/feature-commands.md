# Implemented feature commands

This is the live command inventory, not the list of planned commands. Requirements are in [pseudo-OS architecture](pseudo-os-architecture.md); progress is tracked in the [backlog](pseudo-os-backlog.md).

## Browser-local interface

The mounted desktop exposes `globalThis.jesteros` with:

- `execute(request)`: asynchronous command invocation. Resolves to an applied/rejected result. Applied results wait for the Svelte DOM flush and capture live scroll positions after focus/anchoring/layout effects; they do not claim completion of future media/progress animations. Await each result when sequencing dependent commands.
- `inspect()`: a detached snapshot of supported command names and current window/application state. Changing this snapshot does not change the scene.
- `describe(command?)`: detached, JSON-serializable version-1 catalog for every command, or one requested command. Includes supported profile IDs, capability, request/success-result JSON Schemas, runtime requirements, data/presentation effects, completion semantics, and current target identities. Unknown names reject with unsupported_command; non-string arguments reject with invalid_arguments. Querying never activates a window or changes the scene.

This browser-local feature interface is intended for a future transport adapter, not a WebSocket endpoint or controller UI. Mojave 10.14 and Sonoma 14.0 expose 98 reduced-slice commands each; High Sierra 10.13 exposes 90; Windows 11 23H2 build 22631.2428 exposes 181 native/shared commands. The public object is stable across native scene remounts; retained references dispatch into the active scene. During transition dispatch/discovery reject unavailable, and inspect reports profile:null/transitioning:true rather than exposing outgoing state. The `CORE-04` registry defines immutable profile identity/assets/defaults/stock coverage, selected-profile capabilities and native adapter boundaries; it is not a theme selector.

Requests contain `command`, optional `requestId`, `target`, and `payload`. Command targets/payloads are plain JSON objects; omitted target/payload become empty objects. Explicit null, arrays, unrecognized request fields, unknown commands, and invalid command arguments are rejected. A supplied requestId must be a nonempty string and is echoed in results.

Results are `{ status: 'applied', target: ... }` or `{ status: 'rejected', error: { code, message } }`, plus requestId when supplied. Validation/unavailable-target failures do not apply a scene mutation. Programming errors are not silently translated into successful cues.

## Machine-readable catalog

`frontend/src/command-catalog.js` composes the canonical inventory from shared schemas and native shell/app catalogs. Registration requires exact descriptor/handler parity for the selected profile and seals the handler map. Globally known but unsupported names reject unsupported_profile, not unsupported_command; unregistered features are never advertised. Adding a slice must publish its contract in the same change. Keep the human behavior tables and working notes current.

`jesteros.describe()` returns `{ version:1, profile, profiles, commands, targets }`. Active profile metadata and snapshots identify the actual native scene. Profiles list supported IDs; targets.profiles lists installed profile IDs/names/family/version. Each commands entry has:

- `requestSchema`: [JSON Schema Draft 2020-12](https://json-schema.org/draft/2020-12/schema) for the complete command envelope, including closed target/payload objects and conditional argument rules. [Conditional schemas](https://json-schema.org/understanding-json-schema/reference/conditionals) capture paired context coordinates, mutually exclusive menu positioning, explicit pin payloads, and observational focus constraints.
- `resultSchema`: successful applied-response schema. Returned identities are inside **result.target**, never flattened beside status. app.open returns target.appId/windowId; desktop.open also returns target.fileId; notes.create returns target.noteId; scene.selectProfile returns target.profileId. Rejected responses use the shared error envelope above.
- `profiles`, `capability`, `requires`: current profile support and descriptive runtime prerequisites. Dispatch and composed handlers require both the active profile ID and capability; unsupported_profile rejects before mutation. Discovery omits unsupported commands. Schemas validate JSON shape, not current record/menu availability; handlers remain authoritative for scene-dependent rejection.
- `effects.data`, `effects.presentation`, `completion`: record mutation versus selection/focus/menu/window effects, with promise completion after handler state, Svelte DOM flush, and retained native scroll bookkeeping. No current command promises completion of future media/animation.

Targets contain installed profiles, registered apps/coverage, live desktop-file and window identities, and native state-specific targets. macOS exposes minimized/zoomed windows, Window menus and Notes folder/search/deleted identities. Windows exposes minimized/maximized windows plus `targets.native.shell` panels/files/controls/calendar/notifications. `targets.native.apps.applications[appId]` contains `windows`, each with its exact windowId, data, menus/dialogs and mounted presentation targets, plus `retained` for closed-only data. `targets.applications` remains the common app array; native discovery does not overwrite it. Hidden/inert views are unavailable presentation targets. Queries are detached and follow live changes without activating them.

Common app targets include logical `minimumSize:{width,height}`. Live window targets include detached physical workspace `bounds:{x,y,width,height,scale}` and `resize:{available,edges,minimumSize}`. `edges` lists `n,s,e,w,ne,nw,se,sw`; availability excludes minimized, expanded and global-modal-blocked windows. Querying or mutating these returned objects never changes geometry.

Common application targets report `multipleWindows`, `quitAllowed`, `running`, `active`, `quitting` and `windowIds`. Inspection exposes `activeAppId`, `runningAppIds` and `pendingQuitAppIds` separately from window focus/lifetime. Native application commands accept an optional `target.windowId`, validate ownership, and require it when multiple windows make the target ambiguous. A stale or wrong-owner ID rejects without mutation. Window-local generic text selection is `textSelection`; Snipping's domain `selection` remains its crop rectangle.

```js
const catalog = jesteros.describe('app.open');
const appId = catalog.targets.applications.find((app) => app.name === 'Notes').appId;
const result = await jesteros.execute({ command: 'app.open', target: { appId } });
if (result.status !== 'applied') throw new Error(result.error.message);
const windowId = result.target.windowId;
```

## Inventory

All 59 commands below support the three installed macOS scenes. Unexpected target/payload fields and invalid types are rejected. Application IDs and window IDs are distinct; use returned/live window IDs, including for newly created windows. Closed IDs are never reused within a scene.

### Native scene selection

| Command | Target | Payload | Behavior |
| --- | --- | --- | --- |
| `scene.selectProfile` | `{ profileId }` | `{}` | Selects an installed native profile. Same ID preserves state. A different ID disposes the old scene and mounts fresh native data/windows/menu/focus/scroll state; completion waits for the new DOM and command registration. Unknown IDs reject unsupported_profile before mutation. |

This is profile selection, not migration of incompatible open documents. The default remains Mojave. Subsequent edits/creation use the new profile's fictional Notes epoch, including when its collection is empty.

### Apps and windows

| Command | Target | Payload | Behavior |
| --- | --- | --- | --- |
| `app.open` | `{ appId }` | `{ title?: string }` | Reactivates/restores the most recent window, or reopens retained application data when no window exists. Does not create a duplicate. Optional title updates contextual titles; returns actual appId/windowId. |
| `window.create` | `{ appId }` | `{ title?: string }` | Creates/focuses a fresh independent managed window only when multipleWindows is true. Returns appId/new windowId. Singleton, pending-quit, app-dialog and global-modal barriers reject before allocation. |
| `app.quit` | `{ appId }` | `{}` | Guarded close of all app windows. Returns quit and confirmationRequired booleans. Dirty native prompts return quit:false/confirmationRequired:true; Save/Discard continues and Cancel aborts the pending quit. Protected Finder rejects disabled. |
| `window.focus` | `{ windowId }` | `{ keyboard?: boolean }` | Restores/activates the window. Keyboard focus goes to its root unless keyboard:false; native child-focus observations use false to preserve caret/input focus. |
| `window.close` | `{ windowId }` | `{}` | Closes only the exact window through native confirmation policy. macOS retains the running application, choosing another same-app window or keeping it active with no window; Windows chooses another visible window and clears the app marker after its last close. |
| `window.setMinimized` | `{ windowId }` | `{ minimized: boolean }` | Minimizes or restores/activates/focuses the root. Minimized Notes rejects presentation commands but retains its data and scroll offsets. |
| `window.setZoomed` | `{ windowId }` | `{ zoomed: boolean }` | Sets workspace zoom/restore and focuses the root; minimized targets are unavailable. |
| `window.move` | `{ windowId }` | `{ x: number, y: number }` | Moves a visible normal window, clamped to the work area; physical workspace pixels, finite numbers only. Does not activate a background window. |
| `window.resize` | `{ windowId }` | `{ edge:'e'\|'w', x:number }`, `{ edge:'n'\|'s', y:number }`, or `{ edge:'ne'\|'nw'\|'se'\|'sw', x:number, y:number }` | Sets the selected physical workspace edge coordinates, anchors the opposite edges, and clamps to scaled app minimums and workspace boundaries. Exactly the selected axes, finite numbers only. Visible normal windows only; global modals block it. Returns appId/windowId; resulting geometry is in inspect/describe. Direct calls do not activate a background window; actor grips focus once without stealing child keyboard focus. Also supported in Windows. |

Resize coordinates use the same physical workspace origin as `window.move`, not global screen or logical app-surface coordinates. A corner supplies both axes; a side supplies exactly one. Normal logical dimensions survive minimize, zoom/maximize restoration and viewport refitting. Native scale can decrease in a smaller workspace and recover on enlargement; positions may clamp. Minimum sizes are conservative implemented-layout limits, not researched factory minimums. Repeated same-area layout refresh preserves exact resized bounds.

All installed profiles support `shell.window-create` and `app.lifecycle`. macOS browser-delivered Command/Ctrl+N creates an allowed active-app window outside editable controls; Command/Ctrl+Q quits the active app. Notes keeps its own new-note shortcut. Windows native New Window/Exit controls use the same contracts; Explorer/Edge use Ctrl+N and Notepad uses Ctrl+Shift+N, leaving Ctrl+N as new tab. These do not override shortcuts intercepted by the host.

Window-menu item IDs are `close`, `minimize`, `zoom`, and `window:<windowId>`. Disabled operations reject with `disabled`; removed windows/items reject with `not_found`. File/Dock controls use the current application/desktop registry, not arbitrary DOM selectors.

Desktop discovery publishes `selectedFileIds`, `selectionAnchorId`, rename draft, marquee, placement offsets and actual `itemBounds`. Placements contain CSS translation `x/y` and native slot `originX/originY`; their sums are physical workspace coordinates. The existing completion barrier remeasures/rebases/clamps after the native DOM changes and flushes corrections before acknowledgement. `targets.desktopFiles` includes native renameable/movable flags and optional folderId; Mac `targets.desktop.files/locations` exposes actual name/parent/kind and destination dropAllowed. Windows publishes equivalent desktop state under `targets.native.shell.desktop`; there is no singular selectedFileId compatibility alias.

Mac actors use Command toggling/all/open, Shift ranges, spatial arrows/Home/End, Return single-item rename and marquee/group drag. Windows uses Ctrl toggling/all, F2 rename and Enter open; shared mechanics do not replace native rendering/menus. Inline editors commit with Enter, cancel with Escape and retain invalid drafts. Copy-modifier drag and batch rename are unavailable. Mac volume movement and Windows system-shortcut rename/movement reject; macOS Trash lifecycle and broader Finder operations remain queued.

### Mojave and Sonoma desktop Stacks

Only `macos-mojave-10.14` and `macos-sonoma-14.0` advertise `shell.desktop-stacks`. High Sierra/Windows omit all eight commands and reject known Stack requests with unsupported_profile before mutation. General menu-bar implementation remains separate; these native actions are available through desktop context menus, view options, keyboard and real stack headers.

| Command | Target | Payload | Behavior |
| --- | --- | --- | --- |
| `desktop.stacks.set` | `{}` | `{ enabled:boolean }` | Enables/disables derived document groups. A transition clears selection/context/draft/expansion/covers and focuses the desktop; retains group/sort preferences and real saved positions. Returns enabled. |
| `desktop.stacks.group` | `{}` | `{ by }` | Requires enabled Stacks; six modes below. A change collapses old groups and clears obsolete focus/selection/covers; preserves an active inspector, but restores desktop focus when replacing its context/header. Returns by. |
| `desktop.stacks.sort` | `{}` | `{ by }` | Requires enabled Stacks; eight modes below. Reorders actual member IDs while retaining valid expanded groups and the browsed cover identity. Returns by. |
| `desktop.stacks.expand` | `{ stackId }` | `{ expanded:boolean }` | Expands/collapses this live group independently, clears file selection/context/draft and focuses/reveals its actual header. Returns stackId/expanded. |
| `desktop.stacks.browse` | `{ stackId }` | `{ direction:'previous'\|'next' }` | Requires a live closed group. Cycles the actual current member with wraparound and retains its ID, not an incidental sorted index. Returns stackId/fileId/index. |
| `desktop.stacks.open` | `{ stackId }` | `{}` | Opens this group's current real cover through desktop.open, including its Preview/window ID and retained last-opened timestamp. Returns stackId/fileId/appId/windowId. |
| `desktop.stacks.focus` | `{ stackId }` | `{}` | Focuses/reveals a live header without creating a synthetic file record. Returns stackId. |
| `desktop.stacks.context` | `{ stackId }` | `{ x:number,y:number }` | Selects all actual member IDs, opens their native file context at the viewport point, and retains the originating header for focus return. Get Info/group-folder/Trash reuse the real batch handlers. Returns stackId/fileId/menuId. |

Group modes: `kind`, `date-last-opened`, `date-added`, `date-modified`, `date-created`, `tags`. Member sort modes: `name`, `kind`, those four date modes, `size`, `tags`. Names use numeric case-insensitive comparison; sizes are largest-first; known dates newest-first and unknown dates last. Folders/volumes never join document stacks. Desktop-wide sort/cleanup/manual position commands reject disabled while Stacks owns the layout; disabling exposes the retained original offsets.

`targets.desktop.stacks` publishes enabled/groupBy/sortBy, expandedStackIds, topFileIds, focusedStackId, live `groups` with stackId/name/fileIds/topFileId/topIndex/expanded/browsing, and actual header `itemBounds`. `targets.desktop.files` exposes createdAt/modifiedAt/addedAt/lastOpenedAt/tags. IDs remain filesystem identities; stacks are derived presentation only. Ranges use grouped member order, including closed members; marquee intersection with a header selects its real members. Direct selection/rename reveals a hidden target before anchoring its editor.

File time is fictional and monotonic in the profile's era, never host time. Actual opening advances lastOpenedAt; an actual parent change advances addedAt, but a no-op move does not. Date groups use UTC Today/Yesterday/Previous 7 Days/Previous 30 Days/month/year and No Date for unknown metadata; Unix epoch zero is a real timestamp. Primary-tag grouping uses the first retained nonempty tag as **simulation policy**, not a claim of verified native multi-tag precedence; a literal tag named `untagged` remains distinct from No Tags. Tag editing and wider filesystem metadata operations remain their own slices.

Native functional evidence: [Apple's versioned Mojave Stacks guide](https://support.apple.com/guide/mac-help/organize-files-in-stacks-mh35846/10.14/mac/10.14), [Sonoma Stacks guide](https://support.apple.com/guide/mac-help/organize-files-on-your-desktop-mh35846/14.0/mac/14.0), [Mojave guide image](https://help.apple.com/assets/5BFDD3F8094622802EEE504F/5BFDD3F9094622802EEE5056/en_US/7ec155addafd69b47524c9b3bbac31a1.png), and [period Mojave shortcut/browsing demonstration](https://9to5mac.com/2018/10/08/how-to-use-stacks-macos-mojave-video/).
