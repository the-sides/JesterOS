# Windows 11 Pro — 23H2, build 22631.2428

## Identity and evidence boundary

The profile `windows11-23h2-22631.2428` represents an en-US Windows 11 Pro scene on October 31, 2023, at a fixed fictional 09:41 UTC, with local account Alex Morgan. This is an offline DOM/CSS/SVG screen prop, not Windows running in a browser. Inventory below describes native Windows, separately from the supported local workflows. An inventory entry does **not** imply an implemented app or enabled control.

Microsoft's [Windows 11 release-information table](https://learn.microsoft.com/en-us/windows/release-health/windows11-release-information) has **two** October 31, 2023 rows: **22631.2428**, with no KB article, and **22631.2506**, linked to KB5031455. The former is this profile; the latter is not substituted. [KB5031455](https://support.microsoft.com/en-us/topic/october-31-2023-kb5031455-os-builds-22621-2506-and-22631-2506-preview-6513c5ec-c5a2-4aaf-97f5-44c13d29e0d4) describes the separate optional cumulative update. Do not confuse this build with **22621.2428**, the 22H2 branch.

[KB5027397](https://support.microsoft.com/en-us/topic/kb5027397-feature-update-to-windows-11-version-23h2-by-using-an-enablement-package-b9e76726-3c94-40de-b40b-99decba3db9d) explains the shared 22H2/23H2 core and the enablement-package switch for dormant features. Its current prerequisites reference .2506; it is not independently an app-version manifest or proof that every feature listed for .2506 was active on every .2428 installation. The [dated October 31 announcement](https://blogs.windows.com/windowsexperience/2023/10/31/how-to-get-the-windows-11-2023-update/) establishes the 2023 Update release, Teams (free) replacing Chat, and the System Components management changes.

The [September 26, 2023 first-party UI announcement](https://blogs.windows.com/windowsexperience/2023/09/26/the-most-personal-windows-11-experience-begins-rolling-out-today/) supplies contemporaneous visuals for Explorer, Photos, Paint, Snipping Tool, Backup, security, and Settings. It explicitly says screens are simulated, features vary, and broad availability of many changes was anticipated by November. [September configuration update KB5030509](https://support.microsoft.com/en-us/topic/542780c2-594c-46cb-979d-11116fe164ba) and [23H2 IT-pro release notes](https://learn.microsoft.com/en-us/windows/whats-new/whats-new-windows-11-version-23h2) describe continuous rollout and feature-control boundaries. These are research references, never runtime screenshots.

There is **no verified first-party per-build Store-app version manifest** for this .2428 image in this research. OS version alone cannot determine Paint, Notepad, Photos, Clock, Calculator, Terminal, or Snipping Tool versions after Store updates. No VM/image installation or pixel comparison was performed. The implementation uses an era-bounded design, not an assertion of exact factory pins or pixel-identical app versions. Later 24H2/25H2/2026 Start layouts, phone companion panes, Recall, generative fill, and later Paint/Notepad AI controls are excluded.

## Shell state and integration contract

`windows11-profile.js` exports `windows11Profile`; the shell owns `createWindows11ShellState()`, `createWindows11ShellCommands(shell, context)`, `windows11ShellCatalog`, `readWindows11ShellTargets(shell, context?)`, and the shared derived `windows11DesktopFiles(profile, apps)` read helper. `readWindows11ShellTargets` maps plain fields; it never attempts to clone Svelte proxies. Supplying context publishes actual currently mounted semantic control IDs, application IDs, window/taskbar state and live virtual desktop entries. State-only calls still publish panel/menu/dialog/quick/calendar/notification targets.

Desktop entries `pc` and `recycle` route to `win11.explorer.navigate` with `{folderId:'root'}` or `{folderId:'trash'}`. Live virtual Desktop children (including `call-sheet`) route through `win11.files.open` `{fileId}`; folders route through Explorer navigation. App handlers validate and open/focus before updating documents/folders. Rename/move/trash in the shared filesystem is reflected in desktop labels/visibility. Personalize invokes `win11.settings.navigate` `{page:'personalization'}`. No metadata-only title change pretends to open a file.

Quick settings authority is **only** `native.shell.quick`: `{wifi:true, bluetooth:false, airplane:false, volume:70, brightness:80}` initially. `win11.quick.set` uses target `{control}` and payload `{value}`: boolean for the three radios, finite 0–100 for the sliders. Airplane activation turns the fictional radios off; they can subsequently be enabled independently. Settings reads/changes these exact properties using the same command. Appearance authority is `native.apps.settings.theme/accent/wallpaper`.

`Windows11Desktop.svelte` accepts the existing profile/children/windows/activeWindowId/activeApp/viewState/execute/registerView/onlayout props plus `native`. Its view exports `measureWorkspace`, `focusControl`, `controlIds`, `scrollPanel`, `scrollAreas`, `scrollSnapshot`; registration cleanup is identity-owned by the parent. Shell commands wait for the DOM and retain actual top/left offsets after focus/scroll/state changes. Workspace origin is zero, with a reserved 48px taskbar and **no macOS menu-bar subtraction**. Windows are parent-bounded physical coordinates and scaled logical interiors. `Windows11Window.svelte` accepts native `onmaximize` rather than `onzoom` and renders all children; `maximized` is the parent policy. DOM measurement, pointer capture and refs stay local; all actor changes go through named commands.

### Shell command IDs

All shell commands have profile/capability-gated typed metadata from the shared `defineCommand` builder, closed target/payload objects, and the shared applied/rejected result convention. The capability is `windows.shell`.

- Panels: `win11.panel.open` `{panelId:start|search|quick|notifications}`, `win11.panel.close` optional `{restoreFocus}`; `win11.start.page` `{page:pinned|all-apps}`; `win11.search.set` `{query}`.
- Launch/taskbar: `win11.app.activate` and `win11.taskbar.activate` `{appId}`; common `app.open`, `window.focus`, `window.setMinimized` are guarded composite calls.
- Quick preferences: `win11.quick.set` `{control}` / `{value}`.
- Desktop: twelve typed `win11.desktop.select`, `.select.toggle`, `.select.range`, `.select.all`, `.marquee`, `.position`, `.rename.begin/change/commit/cancel`, `.rename`, and `.move` contracts share only common mechanics. Native `.context.open/close/select/execute`, `.folder.create`, `.trash`, `.sort`, `.cleanup`, `.view.set`, `.properties`, `.personalize`, `.open` and `.show` retain Windows rendering/policy; exact closed arguments/results are in [feature-commands.md](feature-commands.md#native-desktop-context-and-utilities). Context state publishes focused/expanded IDs, not private submenu choices. The previous context/action interface is removed.
- Dialog: `win11.dialog.close` `{dialogId:'properties'}`.
- Notifications: `win11.notification.dismiss` and `.open` `{notificationId}`, `.clear`, `.doNotDisturb` `{enabled}`.
- Calendar: `win11.calendar.move` `{direction:-1|1}`, `.select` `{date:'YYYY-MM-DD'}` constrained to the displayed valid month.
- Focus/scroll: `win11.shell.focus` `{controlId:string|null}` (null means observed focus outside a shell control), `win11.shell.scroll` `{area:start|search|notifications|panel|desktop|properties|taskbar}` / `{top,left?}`; `win11.shell.dismiss` optional `{restoreFocus}`.

Keyboard coverage includes Ctrl+Escape for Start, scene-contained Meta+S/Meta+A for Search/Quick Settings, Escape dismissal/focus restoration, Enter app/file activation, arrow/Home/End navigation within semantic button groups, Shift+F10/ContextMenu on desktop files, and bounded Tab focus in shell flyouts/dialogs. Native windows handle browser-delivered Alt+F4 and Meta+Up/Down through shared callbacks. Outside pointer dismissal is command-driven. Properties blocks background windows/desktop/taskbar with overlay and inert elements; shared app/window and native presentation commands also reject unavailable before mutation. Host shortcuts may be intercepted before reaching the browser; no host-shortcut override is claimed.

Desktop item actors add Ctrl-click toggling, Ctrl+A, Shift ranges, spatial arrows/Home/End, actual marquee, F2 single-item inline rename and group reposition/folder drop. Enter commits draft/opening and Escape cancels draft/drag. Ctrl+Shift+N creates a real folder, Delete trashes selected records and Alt+Enter opens Properties. Item state publishes ordered selectedFileIds, independent anchor, draft, rectangle, actual bounds and CSS offsets with native layout origins. Real virtual files/folders share Explorer/Terminal authority; This PC/Recycle Bin remain protected shortcuts. Whole move/Trash batches validate before writes. Name/Item type/Size ordering clears manual placement; auto-arrange rejects manual positions, alignment preserves group offsets, native 32/44/64 icon sizes and visibility change the actual surface. Hidden icons still permit background real folder creation without an invisible editor. Copy-modifier drag and batch rename remain unavailable.

Normal Windows frames also expose eight edge/corner grips through shared `window.resize`, in physical workspace pixels. Native caption controls and drag regions remain independent. App-specific logical minimums clamp resize; maximize/minimize/restore and viewport refitting retain the chosen normal logical dimensions. Maximized, minimized and Properties-blocked frames cannot resize. Minimums are simulation layout constraints, not measured Microsoft factory limits.

Application lifetime and window identity are separate. Taskbar activation reopens/restores the most recently used app window; window.create explicitly creates another allowed window, and app.quit invokes native guarded close across the group. Explorer, Edge, Notepad, Calculator, Paint, Photos and Terminal support independent windows; Settings, Clock and Snipping Tool keep one represented primary window. Closing one frame leaves siblings intact; closing the last Windows foreground frame clears its running marker. Dirty Notepad Exit restores the exact minimized prompt window and proceeds only through Save/Discard; Cancel aborts the pending quit. Native New Window/Exit menus and browser-delivered Explorer/Edge Ctrl+N and Notepad Ctrl+Shift+N share these commands. See [window-scoped application targets](windows11-apps.md#command-target-and-view-conventions).

## OS-13 native research: task switching and window cycling
