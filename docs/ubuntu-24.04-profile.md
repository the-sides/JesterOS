# Ubuntu Desktop 24.04 LTS — Noble Numbat, Ubuntu GNOME 46

## Choose before inventory: research decision

**Decision recorded October 5, 2026, before this inventory:** the future Linux candidate is **Ubuntu Desktop 24.04 LTS (Noble Numbat), original April 25, 2024 GA release, amd64, Ubuntu's GNOME 46 session**, English (US), US keyboard, default/light Yaru, and the installer's **Default selection (minimal desktop)**. Candidate identifier: `ubuntu-24.04-gnome-46`. It is **NOT installed, registered, advertised, or selectable in JesterOS**. CORE-07 is research only: this document adds no Linux shell, app, assets, profile registry entry, command namespace, or host configuration. Native inventory below is not implementation coverage.

Canonical's [dated April 25 release deep dive](https://ubuntu.com/blog/ubuntu-desktop-24-04-noble-numbat-deep-dive) identifies Noble and GNOME 46 and explains Ubuntu's additions. GNOME's [March 20, 2024 GNOME 46 release notes](https://release.gnome.org/46/) describe the upstream desktop, not a vanilla GNOME session to substitute for Ubuntu. The target is neither an Ubuntu flavor (Kubuntu/Xubuntu/etc.), GNOME Classic, GNOME OS, nor the latest 24.04 point release. GA-era package evidence and later-updated documentation are separated below.

## Baseline and evidence boundary

### What establishes membership, and what does not

- **GA live-image evidence:** Canonical preserves the original [Ubuntu 24.04 desktop amd64 manifest](https://old-releases.ubuntu.com/releases/24.04/ubuntu-24.04-desktop-amd64.manifest), beside the image in the [official original-release archive](https://old-releases.ubuntu.com/releases/24.04/). It establishes packages and snap revisions in that **live image**, not the application list remaining after a Default/minimal installation. The image includes extended apps and installer tools as well as the minimal desktop.
- **Image authentication limits:** the [official SHA256SUMS](https://old-releases.ubuntu.com/releases/24.04/SHA256SUMS) publishes `81fae9cc21e2b1e3a9a4526c7dad3131b668e346c580702235ad4d02645d9455` for `ubuntu-24.04-desktop-amd64.iso`. This was read, not verified against a downloaded ISO or GPG signature. The [ISO file listing](https://old-releases.ubuntu.com/releases/24.04/ubuntu-24.04-desktop-amd64.list) exposes internal minimal manifests and `install-sources.yaml`; those internal files were not extracted, so no exact post-install minimal manifest is claimed.
- **Default/minimal selection policy:** the official Ubuntu seed at frozen pre-GA commit `5cdc3517ca15315fc663f9f9277a9c8bb5188989` distinguishes [desktop-minimal](https://git.launchpad.net/~ubuntu-core-dev/ubuntu-seeds/+git/ubuntu/plain/desktop-minimal?id=5cdc3517ca15315fc663f9f9277a9c8bb5188989), [desktop (extended superset)](https://git.launchpad.net/~ubuntu-core-dev/ubuntu-seeds/+git/ubuntu/plain/desktop?id=5cdc3517ca15315fc663f9f9277a9c8bb5188989), and [live/installer tools](https://git.launchpad.net/~ubuntu-core-dev/ubuntu-seeds/+git/ubuntu/plain/live?id=5cdc3517ca15315fc663f9f9277a9c8bb5188989). Parenthesized packages are recommendations, not unconditional presence on every customized installation. These are distribution policy evidence, **not an observed post-install filesystem**. “Minimal-seeded” below means this policy plus GA-image evidence; no VM installation was performed.
- **Release-level corroboration:** the [Noble release notes, Ubuntu Desktop section](https://documentation.ubuntu.com/release-notes/24.04/#ubuntu-desktop) say the default install is minimal, the extended selection adds applications, Snapshot replaces Cheese in the extended selection, and games are not installed by default. They identify Firefox 124, LibreOffice 24.2 and Thunderbird 115 as release-level series. That page has later edits; it does not override the archived GA manifest or freeze future snap updates.
- **Installer choice terminology:** the [version-scoped Ubuntu installation guide](https://documentation.ubuntu.com/desktop/en/24.04/tutorial/install-ubuntu-desktop/) calls the choices Default and Extended; Extended adds office tools and utilities. It currently mentions a 24.04.3 image and later hardware guidance, so its screenshots are **not proof of original GA pixels**. Network updates, third-party software/drivers/codecs, interactive/autoinstall, disk layout/encryption and account setup are distinct installer choices; none was performed for this research.
- **Upstream UI evidence:** version-tagged GNOME source and documentation establish command/dialog families. Ubuntu patches, hardware, installed services, locale, account configuration, optional extensions and app updates can change visibility. An upstream tag does not prove every menu item appears on Ubuntu. Exact visual geometry and unseen menu ordering remain **unverified**, even where action names are sourced.

## Ubuntu session overrides versus upstream GNOME

The official [`ubuntu-settings` source package 24.04.3](https://launchpad.net/ubuntu/+source/ubuntu-settings/24.04.3), particularly `debian/ubuntu-settings.gsettings-override`, establishes settings defaults. The [Shell 46.0-0ubuntu5 packaging archive](https://launchpad.net/ubuntu/+archive/primary/+sourcefiles/gnome-shell/46.0-0ubuntu5/gnome-shell_46.0-0ubuntu5.debian.tar.xz), member `debian/ubuntu-session-mods/ubuntu.json`, establishes Ubuntu mode's Yaru stylesheet, `prefer-light` color scheme and four enabled session extensions. The [Ubuntu Dock 90ubuntu1 source archive](https://launchpad.net/ubuntu/+archive/primary/+sourcefiles/gnome-shell-extension-ubuntu-dock/90ubuntu1/gnome-shell-extension-ubuntu-dock_90ubuntu1.tar.xz), members `schemas/10_ubuntu-dock.gschema.override` and `docking.js` under the package root, establishes Dock defaults. Canonical's [GA deep dive](https://ubuntu.com/blog/ubuntu-desktop-24-04-noble-numbat-deep-dive) specifically documents accent-color choice and Tiling Assistant's quarter-screen tiling.

Missing desktop entries may not render in the resulting Dock. Keep [favorites settings](https://launchpad.net/ubuntu/+source/ubuntu-settings/24.04.3) separate from [minimal](https://git.launchpad.net/~ubuntu-core-dev/ubuntu-seeds/+git/ubuntu/plain/desktop-minimal?id=5cdc3517ca15315fc663f9f9277a9c8bb5188989), [extended](https://git.launchpad.net/~ubuntu-core-dev/ubuntu-seeds/+git/ubuntu/plain/desktop?id=5cdc3517ca15315fc663f9f9277a9c8bb5188989) and [live](https://git.launchpad.net/~ubuntu-core-dev/ubuntu-seeds/+git/ubuntu/plain/live?id=5cdc3517ca15315fc663f9f9277a9c8bb5188989) membership.

The visual Activities control is especially easy to misdate: [GNOME Shell 46.0 `panel.js`](https://github.com/GNOME/gnome-shell/blob/46.0/js/ui/panel.js) renders **workspace indicators/dots with an expanded active indicator**, while retaining accessible name “Activities.” [GNOME 46.0 overview documentation](https://github.com/GNOME/gnome-user-docs/blob/46.0/gnome-help/C/shell-introduction.page) still uses Activities terminology and older revision text. Use source/dated images to resolve such differences; do not turn that wording into a claim that an “Activities” word label is visible.

## Native window, menu, keyboard and shared-dialog conventions

- **Window chrome is mixed, not universal.** Modern GNOME apps use client-side headerbars with navigation/actions at the start, heading/view switching centrally and menus at the end; other GTK 3, browser, Flutter and LibreOffice windows can differ. [GNOME headerbar guidance](https://developer.gnome.org/hig/patterns/containers/header-bars.html) is a **rolling HIG**, used for terminology rather than frozen GA dimensions. Version-tagged [Text Editor window source](https://github.com/GNOME/gnome-text-editor/blob/46.0/src/editor-window.ui) and [Settings UI](https://github.com/GNOME/gnome-control-center/blob/46.0/panels/system/cc-system-panel.ui) supply era examples. Do not apply macOS traffic lights or a Windows caption strip to every app.
- **Shell window menu:** Take Screenshot, Hide, Maximize/Restore, Move, Resize, Always on Top, Always on Visible Workspace, conditional workspace/monitor moves, Move Titlebar Onscreen when needed, Close. These exact families are in [Shell 46.0 `windowMenu.js`](https://github.com/GNOME/gnome-shell/blob/46.0/js/ui/windowMenu.js); capabilities and current state gate individual entries. Ubuntu's Tiling Assistant adds quarter-screen workflows, documented by [Canonical at GA](https://ubuntu.com/blog/ubuntu-desktop-24-04-noble-numbat-deep-dive). The extension's precise tiled-group chooser and keyboard defaults remain **unverified**.
- **App-owned menus:** primary/hamburger menu, view/overflow popovers, selection context menu, tab context menu, Preferences, Keyboard Shortcuts, Help and About where the app actually defines them. They are local to the application, not one global File/Edit menu. Native secondary families include Open/Save As, replacement/unsaved-change confirmation, New Folder/Rename, Properties, print, search/replace, preferences and authentication/permission prompts. Exact GTK 3/GTK 4/portal chooser differences, print drivers and modal layouts are **not visually verified**; use each app's tagged source, not a single generic “Linux dialog.”
- **Native keyboard map:** Super toggles Activities; Super+A opens applications; Super+V opens notifications/calendar; Super+L locks; Super+Tab and Super+` switch apps/same-app windows; Super+Page Up/Down switches workspaces, Shift moves the current window; Ctrl+Alt+Tab cycles shell focus; Alt+F2 opens command entry; Print opens capture. Common editing uses Ctrl+A/X/C/V/Z; Terminal copy/paste uses Ctrl+Shift+C/V. [GNOME 46.0 keyboard guide](https://github.com/GNOME/gnome-user-docs/blob/46.0/gnome-help/C/shell-keyboard-shortcuts.page). GNOME 46 adds Super+Ctrl+number to request a new window for a favorite alongside Super+number activation ([dated release notes](https://release.gnome.org/46/#system-enhancements)); Ubuntu Dock compatibility and browser delivery require future verification, not a current shortcut claim.
- **Keyboard accessibility:** Tab/Shift+Tab traversal, arrows in appropriate lists/menus, Enter/Space activation, Escape dismissal, Alt mnemonics and keyboard context/window-menu access are native families. [Tagged keyboard navigation](https://github.com/GNOME/gnome-user-docs/blob/46.0/gnome-help/C/keyboard-nav.page), [GNOME 46 Settings mnemonic changes](https://release.gnome.org/46/#massive-polish-effort). Host/browser-reserved keys may never reach a web scene; a future implementation must advertise only delivered and supported commands.

## Future simulation and native-command boundaries

These are research constraints for a later, separately approved implementation, **not new callable APIs**:

1. Keep a clear split between **native evidence** and **represented local behavior**. Only publish an app/launcher/menu/command when its actual scene-local behavior exists; never populate the Linux candidate with generic empty windows or success-only controls.
2. Any future shell/app command must be profile/capability-gated through the repository's existing command conventions. Maintain one shared authority for local preferences, windows/workspaces, fictional files, notifications and dialog modality; commands must report applied/rejected outcomes truthfully. Exact future Linux IDs, reducers and schemas are **not designed or registered by CORE-07**.
3. A future Terminal or Alt+F2 would execute only an explicitly bounded virtual command language. Never route text to bash, `sudo`, apt/snap, `gsettings`, D-Bus, a host filesystem, PTY or arbitrary subprocess. Native commands appearing in documentation are reference material, not instructions to run on the workstation.
4. Network, Bluetooth, sound, brightness, power, screensaver/lock, accounts, permissions, remote desktop/SSH, printing/scanning, drives, backups, software/firmware updates and installation can only be fictional/local or visibly unavailable. No host device discovery, credentials, enrollment, permission grant, notification delivery, clipboard access, camera/microphone capture or shutdown is implied. Host OS/desktop configuration is out of scope.
5. File operations must stay in the shared virtual filesystem. A future print/export/capture must have a real scene-local result or explicit unsupported outcome; copied host screenshots and pretend saved files are not acceptable substitutes.
6. Browser-contained keyboard/focus/scroll/modal behavior requires later verification. Native shortcut evidence is not proof that the browser receives it, and a fictional lock scene is not a security boundary.

## Assets, rights, visual and version evidence limits

- **No runtime assets were created or imported.** Primary screenshots/source are research references, never an image of a whole desktop/app used to conceal absent interaction. There is no Linux screenshot, installed ISO/VM or pixel comparison in this feature.
- **Pinned rights evidence is mixed:** [Yaru 24.04.2 copyright](https://github.com/ubuntu/yaru/blob/24.04.2/debian/copyright) maps general GPL-3.0+, icon/sound CC-BY-SA-4.0 and specific inherited LGPL files. [Adwaita Icon Theme 46.0 COPYING](https://github.com/GNOME/adwaita-icon-theme/blob/46.0/COPYING) offers LGPL v3 **or** CC-BY-SA 3.0 United States, not Yaru's license. These file-level notices must not be flattened into “all Linux icons are free.”
- **Ubuntu Sans is not SIL OFL:** the [exact GA font source package](https://launchpad.net/ubuntu/+source/fonts-ubuntu/0.869+git20240321-0ubuntu1) and [Canonical Ubuntu Font Licence 1.0](https://canonical.com/legal/font-licence) establish font rights with notice, original/derivative naming, redistribution and trademark conditions. Conversion/subsetting requires review; no font binaries or webfonts were imported.
- **Wallpaper attribution gap:** [ubuntu-wallpapers 24.04.2 copyright map](https://git.launchpad.net/ubuntu-wallpapers/plain/debian/copyright?h=24.04.2) explicitly maps `warty-final-ubuntu.png` to CC-BY-SA-4.0 but does not individually enumerate the new default-dark/Numbat filenames. A blanket CC-BY-SA-3.0 entry and specific CC-BY-SA-4.0 entries coexist. Do not claim every Noble wallpaper has verified CC-BY-SA-4.0 attribution; resolve exact filename/hash/author/license before importing.
- **Marks and appearance are separate from component copyright:** [Canonical's IP rights policy](https://canonical.com/legal/intellectual-property-policy) addresses Ubuntu marks, endorsement and trade dress. This research supplies factual attribution and a future candidate name, **not legal clearance** or permission to redistribute branded assets.
- Yaru, Ubuntu Sans, GNOME/GTK icons, wallpaper and app trademarks each need actual source/version/license/provenance review before copying or authoring equivalents. The GA package versions above are evidence anchors, not blanket redistribution licenses. Theme/style/filename references do not prove SVG paths, font metrics, exact colors, wallpaper crop or legal rights.
- Exact top-bar/dock/headerbar dimensions, app-grid layout, padding/radii/shadows, button ordering, Ubuntu patched Appearance/tiling/DING menus, first-login visual state and package-specific dialogs remain **unverified**. Source-backed semantic inventory must not be marketed as pixel-identical Ubuntu 24.04.
- The archived original manifest pins a **live image**; the frozen seeds establish intended selection policy. Neither proves a specific installed machine, every recommended package, configured hardware or post-install snap content. A later fidelity feature would need a non-updated original-GA installation/package snapshot and visual evidence without changing the selected baseline to the current point release.
- Later GNOME features/app substitutions, Ubuntu point-release changes, a rolling current Snap Store UI, optional GNOME apps and host Linux appearance are excluded unless separately evidenced and explicitly chosen. CORE-07 ends at this decision and native inventory; it does not enable Linux selection.
