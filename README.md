# JesterOS

A simulated desktop and applications for actors to use as screen props during film and television scenes. The default screen now depicts **macOS 27 Golden Gate 27.0.1**; it is not a real operating system or an iMessage client.

New feature work targets only the latest stable macOS. Golden Gate is independently source-researched, with its own shell, window chrome, Notes/Messages presentation, original artwork and app roster—not a renamed Sonoma theme. Completed **High Sierra 10.13 (2017), Mojave 10.14 (2018), Sonoma 14.0 (2023), and Windows 11 Pro 23H2 build 22631.2428 (2023)** profiles remain selectable at their existing checkpoints.

## Current implementation

- Rust/Axum backend serves the built frontend and `GET /api/health`.
- Svelte 5 + Vite renders native macOS menu-bar/Dock desktops or the Windows centered-taskbar/Start desktop, with managed application windows.
- macOS Notes supports plain-text creation/editing, search, pinning, trash, and recovery; Finder shows bounded simulated Desktop/location contents and managed Get Info/Desktop view-option utilities. Golden Gate additionally has real Notes export/Print, Finder File actions and a working fictional Print Center queue. System Preferences/Settings has working bounded Dock/Appearance panes. Historical Mac profiles retain Launchpad; High Sierra/Mojave retain classic Dashboard and five local widgets. Golden Gate has neither retired shell presentation. Golden Gate Contacts/Mail have real local Services records; Messages has separate local compositions/sent records alongside its fixed authored sample text and shared-clock date labels. Other uncovered macOS interiors remain launch-only. Windows retains ten functional offline simulations. Wider researched inventories do not imply implemented workflows.
- macOS Messages retains its sample conversation; conversation selection/search/history remain queued. Golden Gate shares one authored instant across its menu clock, dated records, lock and saver, with actual Clock Options and Date & Time controls. Golden Gate has model-driven fictional Battery, Wi-Fi, Sound and Bluetooth menus, real Sound/Bluetooth settings, owned fictional pairing sheets and original offline Music/QuickTime audio playback; historical profiles retain their fixed status presentation.
- All visual assets are local. No env files, API keys, database, authentication provider, or internet connection is required to run an installed build.
- Browser-local `jesteros.execute()` supports **453 commands in Golden Gate**, 178 in Mojave, 163 in Sonoma, 170 in High Sierra, and 190 in Windows. `jesteros.inspect()` exposes detached state; `jesteros.describe()` publishes typed contracts, capabilities, effects/completion semantics and live target IDs. See the [implemented command inventory](docs/feature-commands.md). Golden Gate has bounded Apple, File, Edit, View, Window, Help and cross-app Services workflows, real virtual storage management, confirmed window-reopening choices, fictional Wi-Fi/Battery/Clock/Sound/Bluetooth controls, original offline audio playback, local Spotlight search/previews/answers/privacy, Notification Center stacks/widgets/source-linked banners and actions, real notification app settings and a fictional Print Center queue; Rust control and broader app-specific interiors remain deferred.

## OS profile setup

Open the normal desktop URL for **Golden Gate 27.0.1**. Explicit installed IDs are `?profile=macos-golden-gate-27.0.1`, `?profile=macos-high-sierra-10.13`, `?profile=macos-mojave-10.14`, `?profile=macos-sonoma-14.0`, and `?profile=windows11-23h2-22631.2428`. Unsupported/empty/inherited IDs show a setup error rather than a substitute desktop. Profile identity, capabilities, assets/defaults, stock-app coverage and installed targets are inspectable.

```js
await jesteros.execute({
  command: 'scene.selectProfile',
  target: { profileId: 'macos-sonoma-14.0' },
});
```

A different profile starts a **fresh native scene**, resetting fictional records, windows, menus, focus and scroll; selecting the current ID retains state. The stable `jesteros` object follows the new scene, including cached controller references. Await selection before dependent commands. Notes timestamps and Windows Clock use fictional profile-local time, never host time. Existing historical [profile research](docs/pseudo-os-architecture.md#implemented-profile-boundaries) remains available; it is not a promise of further cross-era feature parity.

Conditional [Linux research](docs/ubuntu-24.04-profile.md) selects **Ubuntu Desktop 24.04 LTS (original April 25, 2024 release), Ubuntu GNOME 46 session**, not generic Linux or vanilla GNOME. No Linux desktop, app registry, runtime assets or commands are installed; its candidate ID `ubuntu-24.04-gnome-46` is deliberately absent from discovery and rejects as unsupported. The inventory separates Default/minimal, extended and optional apps; exact GA package/snap evidence and visual/rights limits are recorded.

## Golden Gate fictional sessions

- Apple menu → **Lock Screen**, delivered **Control+Command+Q**, or the page alias **Control+Shift+F7** locks the retained desktop. The credential form explicitly says to use the fictional password **`scene`**, never a real password. Wrong input visibly errors; Back/Escape cannot bypass sign-in.
- **Login Window…** offers fixed local profiles Alex Morgan/Casey Rivera and Guest User. The disclosed page-local checkbox enables the optional upper-right fast-user-switch menu; this is not the native Menu Bar settings pane or administrator account management.
- Each signed-in local profile retains its original independent desktop, Notes data/editor/caret/scroll, windows and appearance. Inactive/locked scenes are inert; their global app shortcuts are paused. Switching does not copy or reopen documents.
- Guest requires a deletion acknowledgement, not a password. Log Out presents a real confirmation: Cancel restores the original Guest focus/selection; **Delete Files and Log Out** discards only that Guest scene and returns login choices. A later Guest login starts fresh; local scenes survive.
- These thirteen `session.*` commands exist only in Golden Gate. Historical profiles reject them as `unsupported_profile` without mutation. Local Log Out signs out only the departing account and retains its desktop/data for a later fictional login; Guest Log Out discards its ephemeral scene. Reload/profile replacement resets all fictional users; host authentication/accounts, actual FileVault, user creation, recovery, biometrics and automatic saved-session loading are not implemented.
- Primary sources: [Apple latest-version table](https://support.apple.com/en-us/109033), [macOS 27 overview](https://www.apple.com/os/macos/), [versioned app roster](https://support.apple.com/guide/mac-help/apps-on-your-mac-mchl110b00b7/27/mac/27), and [fast user switching](https://support.apple.com/en-is/guide/mac-help/mchlp2439/mac). Shell/app/session skins are original, source-informed approximations; there is no native VM/factory-pixel equivalence or redistributed Apple/SF artwork claim. The virtual roster does not implement iPhone pairing, AI services or optional App Store apps.

## Golden Gate page-local power

- Apple menu **Sleep**, **Restart…**, and **Shut Down…** operate only inside this page. Restart/shutdown normally show real Cancel/default-action confirmations; Escape cancels, Return accepts, and Tab stays in the dialog. Holding Option removes their ellipses and explicitly bypasses that action confirmation; `confirm:false` expresses the same intent in the command API.
- Delivered **Control+Shift+F5** starts the original wallpaper-drift screen saver; **Control+Shift+F6** sleeps; **Control+Shift+F4** wakes/starts the simulated Mac. A key, click or actual mouse movement dismisses the saver; sleep accepts a key/click. Wake input is consumed and never signs a user in.
- Sleep is black; shutdown remains black until the page-local start action. Startup shows an original white logo/progress bar for **five fictional seconds**, then unauthenticated login choices. `power.advance` advances only saver/startup presentation, never the authored shared scene clock. Automatic presentation ticks pause in hidden pages and stop on phase change/disposal.
- Accepted or explicitly bypassed power cycles sign out all fictional users, retain the original local desktops/documents/windows/appearance, and discard only Guest data. Cancellation preserves even the original private credential draft/caret; normal confirmation warns about active **or inactive** signed-in Guest data before deletion. Reopening locals is a fixed disclosed simulation policy, not an enabled fake “Reopen windows” checkbox.
- Nine `power.*` commands are Golden Gate only. No host power/authentication/settings/storage, recovery, saver preferences, unsaved-document handling or configurable reopen policy is implemented. Those broader native sub-interfaces remain separately queued.
- Primary sources: macOS27 [sleep/wake](https://support.apple.com/guide/mac-help/put-your-mac-to-sleep-or-wake-it-mh10330/27/mac/27), [restart/shutdown](https://support.apple.com/guide/mac-help/shut-down-or-restart-your-mac-mchlp2522/27/mac/27), [screen saver](https://support.apple.com/guide/mac-help/use-a-screen-saver-mchl4b68853d/27/mac/27), [Wallpaper → Screen Saver settings](https://support.apple.com/guide/mac-help/change-screen-saver-settings-mchlp1227/27/mac/27), and [hardware-neutral startup symbols](https://support.apple.com/en-us/102675). Original SVG/CSS, simplified drift and deterministic startup are source-informed, not factory timing/pixels or Apple artwork redistribution.

## Golden Gate scene fixtures

`scene.reset` removes the Golden Gate browser-local saved-session slot and restores the default fixture; `scene.replaceSeed` installs a complete version-1 Notes/files/printing/editing/viewing/communications/system/Messages/appearance/Dock fixture without changing that slot. Both dispose every fictional user root, discard edits and return an awake default local desktop with Messages ready, including from lock, Guest, confirmation, sleep or startup. These are browser API setup operations, not actor-desktop controls. Invalid seeds and storage failures reject before disposal.

```js
const seed = jesteros.describe().targets.sceneSeed.seed;
seed.messages.thread.items = [{ kind: 'text', direction: 'outgoing', text: 'Cue fixture.' }];
await jesteros.execute({ command: 'scene.replaceSeed', payload: { seed } });
await jesteros.execute({ command: 'scene.reset' });
```

The detached seed is the initial baseline, **not an export of live edits or a saved session**. Each fictional user receives an independent clone. Replacement never merges or overrides profile identity/generated app bundles; invalid complete seeds reject before disposal. Same-profile selection preserves the replacement; reload or leaving/returning restores defaults. See [schema, limits and boundaries](docs/feature-commands.md#scene-reset-and-complete-seed-replacement). Seed replacement does not save data or invoke external media, host services or an operator panel.

## Golden Gate app retention and optional saved sessions

Closing the last ordinary app window or quitting retains its model, title, normal/zoom restore geometry, Finder location/selection, Settings pane and owned native view state. Reopening allocates a fresh window ID on the current ordinary desktop; it does not revive a closed full-screen/minimized presentation. `window.create` remains fresh. Notes preserves matching-note caret/selection and actual scroll, including readonly Recently Deleted readers.

```js
await jesteros.execute({ command: 'scene.session.save' });
await jesteros.execute({ command: 'scene.session.restore' }); // Awake, signed-out login.
await jesteros.execute({ command: 'scene.session.clear' });   // Storage only; live scene unchanged.
```

Saving is explicit and browser-origin-local, never automatic. Reload still starts the default scene; restore requires fictional sign-in and never restores authentication. The bounded, validated version-1 slot retains local users' current models, windows, Spaces/Split View, Dock order, generated-file timestamps and semantic view state. Guest, private credential/join drafts, authentication, power phases and transient menus/gestures are excluded. Authored fictional Wi-Fi fixture passwords are model data, not private drafts or real credentials. Clear removes only this slot; `scene.reset` also clears it. Quota/denied-storage failures reject honestly. No Rust/controller persistence or actor/operator panel. See [storage format, limits and failure behavior](docs/feature-commands.md#app-retention-and-explicit-browser-local-saved-sessions).





## Application switching and visibility

- Delivered Command+Tab on macOS switches between running applications; delivered Alt+Tab on Windows switches between actual managed windows. Hold the modifier to browse, add Shift to reverse, and release to activate. Arrow keys/Home/End choose; Enter/Space or click activates; Escape cancels, as does Period on macOS. Selection does not change foreground ownership or restore windows.
- macOS includes hidden, all-minimized and zero-window running apps. Activation unhides the group but never reopens or unminimizes it; Dock activation remains the explicit restore/reopen path. Held Command+H toggles the selected app's visibility, and held Command+Q uses its real guarded quit. Finder cannot quit.
- Click the native macOS application heading for Hide, Hide Others, Show All and guarded Quit; Up/Down opens at the last/first enabled item. Golden Gate additionally has real About, Notes Settings and relevant local Services below; historical About, Preferences/Settings and Services rows remain disabled. Hide/Show retains edited data, original views, caret ranges and normal/minimized/restore geometry. Show All preserves foreground ownership.
- Hiding the active app hands foreground to the next nonhidden running app. If all others are hidden, the scene unhides another running app, preferring Finder; a sole running app cannot hide. This fallback, stable creation-order cycling and disabling menu visibility no-ops are explicit browser policies, not measured AppKit edge rules.
- Delivered Command+grave-accent cycles visible, nonminimized windows of the current macOS app; delivered Alt+Escape cycles eligible Windows windows in creation order. Windows cards contain the actual inert managed surfaces and restore the exact selected minimized window; their close control uses the real unsaved-document workflow.
- **Browser-safe in-page aliases:** Control+Shift+F3 opens a persistent switcher; Control+Shift+F8 cycles windows. Native Control+Alt+Tab also opens the persistent Windows switcher if delivered. The OS/browser may consume native chords, function keys or modifier release before the page receives them. Control+Tab/Control+Shift+Tab remain browser-owned; no host bindings/settings are changed. Direct commands are the reliable non-keyboard path.

Fixed/launch-only interiors have conservative layout limits, not measured factory minimums.

- Dock dots represent application lifetime, including apps with minimized or no windows. Finder always runs and cannot quit. Browser-delivered Command/Ctrl+N creates a window for a multi-window active app outside text inputs; Command/Ctrl+Q quits the active application. Notes retains its own new-note shortcut and single collection window. Window/application state resets on reload; Rust does not persist or synchronize it.

## Notes

Open Notes from the Dock. The three-pane light UI follows Apple's **macOS Mojave 10.14** Notes guide, not the modern app.

- Use New Note, or **Command-N / Ctrl-N**, then edit the title and multiline body. Changes immediately update the note list; an empty title appears as “New Note.”
- Search filters title/body text in the selected folder, ignoring case and extra whitespace. In Golden Gate, **Command-F / Ctrl-F** opens in-note Find and **Option-Command-F** focuses Search Notes; historical Mac profiles retain Command-F/Ctrl-F search. Editing a result clears the filter so the same note keeps focus.
- Right-click a note, or focus it and press **Shift-F10**, to pin/unpin or delete it. Arrow keys and Home/End navigate the list and context menu; Escape dismisses the menu.
- Delete moves notes into **Recently Deleted**, where they are read-only. Restore returns them to Notes with their text and pin state retained. Empty collections disable actions that require a selection.
- The toolbar toggles the folder sidebar. Text, selection, search, pin state, and sidebar preference survive minimizing or closing/reopening Notes. **Reload resets the fictional scene**, including edits and deleted notes.
- This is session-local plain text, not iCloud or the host's Notes database. Rich-text formatting, tables, checklists, attachments, sharing, locking, custom folders, and permanent deletion are not implemented; their controls are omitted rather than presented as working.

Primary-source screenshots, UI observations, implementation decisions, defects/fixes, and verification notes are in [Mojave Notes research and working notes](docs/notes-mojave.md).

### Golden Gate Edit workflows

- Native **Command/Ctrl-C, X, V, A, Z and Shift-Z** operate the simulation clipboard and logical undo/redo, never the host clipboard. Title/body share each note's history; Search Notes and owned Find/spelling drafts retain their own histories. Empty Copy/Cut leaves the previous clipboard intact. Recently Deleted remains readonly.
- **Command-F**, Command-G/Shift-Command-G, Command-E and Command-J use the real inline Find bar, literal whole-note title/body matches, optional case/whole-word filters and native selection/scroll. Replace/Replace All treats `$&` literally and creates one document undo transaction. All matches remain navigable; only500 are highlighted.
- Spelling and Grammar uses the bundled **English (United States) Hunspell dictionary**, with actual suggestions, per-note Ignore, root-local Learn/Unlearn, optional live underlines and conservative completed-word autocorrection. Smart Quotes, Smart Dashes and configured literal replacements work on typing or explicit Replace Selection/All. Grammar, smart links, AI writing tools and rich-text-only actions remain disabled.
- Finder Copy/Paste clones current live user subtrees with independent IDs and collision names. Global file undo/redo includes creation, rename, move and trash; intact versioned deltas preserve unrelated records, allocators and clocks. Protected built-in apps/anchors are not copied. Native Save name/tags and Desktop rename share text clipboard/history without borrowing another pane's owner; Save keeps only its application Edit menu enabled.
- Histories are bounded browser policies: text64 transactions/4Mi UTF-16 before+after values; Finder64/8Mi deltas. Persistent V1 `editing` includes preferences, up to1024 learned words and1024 replacement pairs. Explicit local saves restore independent users' preferences, not clipboards/history/find/ignored words/drafts; incomplete older V1 inputs reject. Dictionary notices are served at `/licenses/dictionary-en.txt` (MIT/BSD); missing assets fail honestly, and disabling autocorrection restores typing.

### Golden Gate View workflows

- Notes **Command-1/2** switches List/Gallery; actual text cards open detail with double-click or Return, and Command-Return returns to Gallery. New Note opens detail and focuses its title. Show Sidebar, Show Note Count and folder-specific sorting operate on real records; Recently Deleted keeps the global default sort and remains readonly.
- **Shift-Command-period/comma/0** changes or resets the current note's display zoom from50% to200%, independently of default text size. Zoom preserves text, timestamps, native selection and undo history. Hidden Gallery editors cannot borrow Find/spelling availability.
- Finder **Command-1/2/3/4** selects Icons/List/Columns/Gallery. Sorting, real metadata groups, list-header reversal, text previews and current selection use the actual virtual files. Single-clicking a folder in Columns browses into it without dropping the view; explicit folder preferences override the window's browsing mode.
- View controls own each Finder window's toolbar/sidebar/path/status/preview. Hiding the toolbar also hides the sidebar and moves visible status to the top. **Command-J** opens the owned nonmodal View Options pane; real selectors/sliders adjust mode, arrangement, icon size, spacing and text size. Escape closes only that pane.
- Required V1 `viewing` persists folder preferences, note counts/sort and per-note zoom; ordinary-window presentation persists with explicit local sessions. Alex/Casey remain separate, and accepted Guest logout discards Guest changes. Complete seeds and saved sessions reject missing/invalid View state before disposal. Unsupported attachments, toolbar customization, inherited “Always Open In” policies and launch-only app interiors remain unavailable.

## Run the desktop at localhost:3000

From the repository root:

```sh
bun install
bun run build
bun run start
```

Open **http://localhost:3000**. Rust serves both the desktop and API from one origin. Stop with Ctrl-C.

The backend refuses to serve the desktop if `frontend/dist/index.html` is missing, and prints the build command. Missing static assets return 404; there is no single-page routing fallback.

For a trusted local network:

```sh
bun run start -- --bind 0.0.0.0:3000
```

Open `http://<host-machine-LAN-IP>:3000` from the other device. This build has no authentication; do not expose it to an untrusted network or the public internet.

## Future controller-to-puppet boundary

The intended flow is **controller device → Rust backend → puppet screen(s) → feature command handlers**. The puppet is the actor-facing desktop; the controller is a separate operator interface. Neither the controller nor its WebSocket transport/protocol is implemented in this iteration. Transport-neutral feature command interfaces are required during pseudo-OS development, before controller integration.

Future operator cues include incoming fictional messages, low-battery notifications, and a simulated zero-battery/power-off appearance. Every feature—not just these cues—must be command-addressable through the shared behavior interface, including app editing/navigation and menu/dialog presentation. Those effects must change the simulated screen only, never the host machine's files, battery, or power state. Actor interactions use the same feature handlers as equivalent remote requests.

Rust should own shared scene/take state and saved messages, with SQLite persistence. WebSockets should deliver state changes to paired screens, acknowledge applied cues, and restore current state after reconnecting. Scenario templates and individual takes should be separate so a reset can begin a fresh take without erasing prior messages. These are design boundaries, not existing endpoints or functionality.
